1. Classical IR
   - Inverted Index, Ranking
   - parallel indexing : map reduce, spark
   - term-document matrix : corpus (sparse matrix). vocab축-document축. doucment 1개 = column vector (sparse vector)
   - inverted index = (term, posting list) -> dense row representation
   - sparse retrieval : frequency를 normalization한 값으로만 보면 'is'와 같이 자주 등장하는 단어에 매핑되서 점수가 높은 현상이 발생
   - TF-IDF : Term Frequency (Document내 Frequency를 normalization) * Inverse Document Frequency (ln(문서갯수/단어 등장한 문서 갯수))
   - IDF는 0일때 정의가 안되는 문제점 있음. => 0일때도 정의가 되도록 수식을 바꿔서 BM25로 해결
   - document 길이가 다름에 파생된는 문제점이 있음. => 평균 문서길이로 보정을 해서 BM25로 해결
   - relevance score : 문서내 단어들의 TF-IDF값을 모두 더한 값. 문서가 특정 query와 얼마나 관련있는지

2. IR metrics
   - classification task : (image, class label)
   - ranking task :  (Query, ranked list of documents)
     -> 1~1억등까지 순서를 매긴 리스트 -> cost가 많이 들고 힘듦
     -> 1~3등까지 순서를 매긴 partial ranked list를 만들어서 학습 -> 이것도 힘듦
     -> 1~3등까지 순서는 매기지 않고 relevent document를 만들어서 학습
   - success and reciprocal rank : MRR@K. Success@K, RR@K
   - Precision@K : 반환결과의 정확도. K등내에서 맞춘 비율
   - Recall@K : 전체 관련도 문서 중에 K등내에서 맞춘 갯수

3. BERT
   - pre-training : Next Sentence Prediction과 Mask를 맞추는 2가지 task 수행
   - fine-tuning : downstream task에 맞게 학습
   - cross-encoder : 쿼리, 관련있는문서, 관련없는 문서를 통해 loss를 구함. 10억개의 문서면 10억번 cross-encoder를 돌려야해서 어려움
   - DPR : bi-encoder. vector db를 이용하여 빠르게 찾아옴
